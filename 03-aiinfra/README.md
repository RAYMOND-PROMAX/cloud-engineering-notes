# 第三章：AI Infrastructure

> 从 GPU 计算基础到大模型服务工程化：先理解技术，再完成实践。

AI Infrastructure（AI 基础设施）不仅是让模型在 GPU 上运行，还涉及计算资源、集群调度、推理与训练、模型服务、可观测性及系统可靠性。

本章采用 **「技术教学 + 工程实战」** 两部分结构：前半部分系统理解技术原理与运行机制；后半部分通过可复现的实验，将不同组件组合成能够部署、观察、测试和维护的系统。

## 学习目标

完成本章后，希望能够：

- 理解 GPU、CUDA、容器与 Kubernetes 在 AI 工作负载中的分工。
- 解释 GPU 资源分配、任务调度和推理引擎内部调度的区别。
- 理解大模型推理的 Prefill、Decode、KV Cache 与 Continuous Batching。
- 使用指标、日志与实验结果分析服务延迟、吞吐和资源瓶颈。
- 独立搭建基础推理环境，并逐步扩展至 Kubernetes 集群。
- 通过压力测试、故障演练和结果验证积累可复用的工程经验。

### 实验文档统一格式

1. **实验目标**：要验证什么问题？
2. **环境与前提**：硬件、软件版本、依赖与限制。
3. **操作步骤**：命令、配置及其作用。
4. **运行观测**：使用哪些指标、日志与命令观察系统？
5. **异常与排查**：可能出现什么问题，如何定位？
6. **验证结果**：预期结果与实际结果是否一致？
7. **结论与复盘**：本次实验说明了什么，还有哪些未验证之处？

## 文档原则

- **先理解，再操作**：不只记录命令，还解释关键机制与配置含义。
- **区分事实与实验**：官方文档、参考文章、推导结论和亲自验证的结果分别标注。
- **版本可追溯**：涉及 Kubernetes、GPU Operator、vLLM 等组件时注明适用版本与硬件条件。
- **不虚构数据**：没有实测的吞吐、延迟、性能收益或故障现象不写成实验结论。
- **避免重复**：共性技术在教学部分集中讲解，实战部分引用相关概念并专注于操作与验证。
- **持续修订**：目录和实验可随着技术资料、版本变化和复现实践逐步调整。
